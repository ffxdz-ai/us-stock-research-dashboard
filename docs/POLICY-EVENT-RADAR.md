# 政策预期差与会后确认

系统不再从“加息/降息”方向直接推断股票涨跌。日报先比较三层证据：

1. **决定相对会前预期**：只接受政策公布前已存在、可追溯的预期记录。没有精确时刻时可用有来源的 `morning_pre_release`，不得编造分钟级时间。
2. **未来政策路径**：比较最新和前次的美联储 SEP 年末政策利率中位数。当前决定符合预期，不代表后续路径宽松。
3. **会后市场验证**：以 FRED 日收盘数据，比较会前收盘与会后第二个交易日收盘的 S&P 500、纳斯达克综合指数、道指、2/10 年美债收益率与 WTI。指数上涨数量只是参与度代理，不等同真实市场广度；日收盘变化也不能证明涨跌完全由政策引起。

本层的结果写入 `docs/data/policy_event_radar.json`、`docs/data/index.json` 的 `policy_event`、独立的政策事件报告和 DeepSeek 公共上下文。它只为选股提供风险情境，**不提高机会分，不跳过证据、入场价、止损价、目标价或 R/R 硬门槛，也不单独产生买入通知**。事件超过七天后自动标为历史复盘。

## 下一次会议如何更新

在 `config/policy_events.json` 的 `events` 中新增一条事件，至少填写：事件日期/公布时刻、公布前的预期幅度及来源、实际幅度及美联储原文链接。若有新版 SEP，再填写年末利率中位数与前次值。会前预期来源必须标注早于公布时刻；不能把会后评论冒充会前预期。缺失字段会显示“待确认”。

工作流沿用现有 `FRED_API_KEY` GitHub Secret；无须新增密钥。政策雷达复用同一轮宏观采集的 FRED 日观察值，避免重复请求与接口节流。FRED 请求失败时仍生成日报，但会后确认保持待确认并写出缺口。当前模块**不会自动采集未来会议的会前概率或自动解析新的美联储声明**；这些事件事实需先经过人工核对后录入配置。后续如接入可信的历史 Fed Funds 期货预期源，可以替换这一步，但必须保留公布前时间戳。
